# 숏줍개발 MSI 환경

## 사용자 지시: 완전 자동 승인 모드

2026-11-15 사용자는 MSI의 타닥·숏줍개발·숏줍대본 세 작업공간을 완전 자동 승인 모드로 열었다고 확인했다. 이후에도 각 공간의 Codex와 Claude Code는 완전 자동 승인 모드로 시작하고 재시작한다. 이는 사용자가 명시한 실행 모드다.

- Codex는 `--dangerously-bypass-approvals-and-sandbox`를 사용한다. 명령 승인 확인과 실행 샌드박스를 해제하는 옵션이다.
- Claude Code는 `--dangerously-skip-permissions`를 사용한다. 도구 실행 권한 확인을 생략하는 옵션이다.
- 기존 프로젝트 경로, 프로젝트 전용 `CODEX_HOME`을 사용하는 구성, 현재 MSI 대화 이력과 pstack 연결을 유지한다. 재시작하면서 읽기 전용 또는 요청 시 승인 모드로 되돌리지 않는다.

아래 예시의 `CODEX_SESSION_ID`와 `CLAUDE_SESSION_ID`에는 이 프로젝트에서 이어갈 현재 MSI 대화 식별자를 설정한다. 실제 식별자는 공개 문서에 기록하지 않는다. 프로젝트 전용 `CODEX_HOME`이 있는 경우 기존 시작 환경을 유지한 채 실행한다.

```bash
cd "$HOME/Projects/shorts-automation"
codex resume "$CODEX_SESSION_ID" --dangerously-bypass-approvals-and-sandbox
claude --resume "$CLAUDE_SESSION_ID" --dangerously-skip-permissions
```

승인 생략은 파일 수정과 셸 명령도 확인 없이 실행할 수 있게 한다. 이 설정은 기존 프로젝트의 작업 범위와 운영 실행 제한을 바꾸지 않는다. Gemini·Antigravity 중지 지시와 별도 제작·배포 승인 범위는 계속 적용한다. 로그인과 최초 신뢰 화면은 사용자가 처리하며 이 문서 갱신으로 자동 선택하지 않는다.

이 절은 최초 구축 때의 읽기 전용·요청 시 승인 실행 예시를 대체하는 최신 사용자 지시다. 아래 초기 화면과 확인 대기 기록은 당시 관찰 결과로 보존한다. 현재 자동 모드 실행 여부는 사용자 확인에 근거하며, 이번 문서 수정에서 각 프로세스를 재시작하거나 실행 인수를 다시 검증하지 않았다.

확인일: 2026-11-15
초기 구축 당시 상태: **PARTIAL_WAITING_USER**. 독립 개발 작업본, 의존성, 두 에이전트 창, 프로젝트 이력과 pstack 연결은 준비했다. 최초 사용자 확인 화면 이후의 대화 로딩과 응답 검증은 남아 있다.

## 배치

- 개발 작업본은 `~/Projects/<development-project>`에 둔다.
- 초기 보관본과 기존 개발 작업본은 유지하고 새 경로를 독립 Git 저장소로 구성한다.
- 운영 봇·큐·예약·DB·미디어는 기존 운영 장치에 남긴다. 데스크톱을 운영 노드로 등록하지 않는다.
- 기존 Herdr 서버를 재시작하거나 다른 프로젝트 창을 변경하지 않고, 전용 작업공간에 Codex와 Claude를 좌우로 배치했다. 생성은 `--no-focus`를 사용했다.

## 자료와 의존성

코드·미커밋·미추적 자료를 제외 정책과 함께 복사하고 checksum dry-run으로 비교했다. Git 내부 메타데이터와 재생성 의존성은 내용 비교에서 구분한다. 코드 및 문서의 비교 대상 일반 파일 4,061개에서 추가 전송 필요 파일은 없었다.

운영 환경 파일, 인증, 개인키, 운영 상태와 DB, 가상환경, 의존성 디렉터리와 캐시는 일반 코드 전송에서 제외했다. 외부 worktree 등록은 별도 보관해 새 독립 저장소에 유효하지 않은 활성 등록이 남지 않도록 했다.

Python 가상환경을 새 경로에서 만들고 기존 개발 환경의 고정 패키지 목록으로 재설치했다. `pip check`와 Gateway의 `npm ci --ignore-scripts`를 검증했다. 기존 개발 작업본이나 전역 도구를 덮어쓰지 않았다.

## 프로젝트 이력 연결

- 프로젝트에 속한 Codex JSONL 613개를 별도 프로젝트 이력 공간에 복사했다. 실행 중인 원본 대화는 완전한 줄 경계의 스냅샷으로 보존했다.
- Claude 프로젝트 JSONL 326개를 새 프로젝트에 대응하는 이력 디렉터리에 복사했다.
- 이어갈 두 원본 대화는 해시로 확인했고, 나머지 복사 대상은 checksum 비교로 검증했다.
- Codex는 프로젝트 전용 `CODEX_HOME`에서 기존 대화를 `fork`하도록 구성했다. 기존 인증은 재사용하며 이 작업에서 인증을 새로 복사하지 않았다.
- Claude는 기존 대화를 `--resume`과 `--fork-session`으로 이어가도록 구성했다.
- pstack 배포본을 프로젝트 전용 위치에 보존하고 두 에이전트의 프로젝트 스킬 경로로 연결했다. 다른 작업공간·전역 스킬 설정은 바꾸지 않았다.

이력 파일의 전송 성공은 실제 대화 로딩 성공과 다르다. 원본 대화, 초기 보관본과 노트북 자료는 삭제하지 않았다.

## 초기 구축 당시 화면과 사용자 확인 대기

Herdr의 `idle`/`interactive_ready` 표시는 완료 증거로 사용하지 않았다. 실제 터미널을 읽어 다음 화면을 확인했다.

1. Codex: 새 프로젝트의 **Folder access / Trust this folder?** 화면. 사용자가 해당 경로를 확인하고 신뢰 여부를 직접 선택해야 한다.
2. Claude: **Choose the text style** 최초 테마 화면. 사용자가 직접 선택해야 한다. 별도 상태 조회에서는 로그인 미완료도 확인돼 사용자 로그인이 필요하다.
3. 초기 설정 이후 추가 프로젝트 신뢰나 권한 화면이 나오면 사용자가 직접 확인한다. 이후 기존 대화가 실제 표시되는지, 새 세션으로 분기됐는지와 읽기 전용 인수인계 응답을 확인해야 한다.

시작 안내는 프로젝트 지침과 인수인계를 읽고 현재 경로·Git 상태를 짧게 확인한 뒤 대기하는 범위다. 새 기능 개발이나 콘텐츠 작업은 배정하지 않았다. 초기 신뢰·테마·로그인 UI는 자동 승인하지 않았고 권한 우회 옵션도 사용하지 않았다.

## 검증 범위

- 독립 작업본 파일 내용 비교, 프로젝트 이력 전송과 대표 대화 해시 확인.
- 새 가상환경의 의존성 검사와 Gateway 의존성 설치.
- 외부 네트워크를 차단하고 loopback만 허용한 관련 Python 회귀 **146개**, Gateway Node 테스트 **11개**, Gateway 자체 검사 통과.
- 기존 전체 검사에서 확인한 20개 실패는 노트북과 동일한 기존 기준선이다. 이번 문서는 전체 저장소의 모든 테스트가 통과했다는 뜻이 아니다.
- 새 경로에서 전체 저장소 검사를 다시 수행하거나, 실제 모델 생성·운영 배포·RDP 화면을 검증한 결과는 아니다.

Gemini/Antigravity는 사용자 지시로 제외한다. 운영 실행, 신규 유료 API 요청, provider·예산 변경을 하지 않았다.

## 안전한 복원과 재개

1. 보관본을 삭제하지 않고 새 프로젝트 경로에 별도로 복원한다. dirty 작업본에 reset/clean이나 전체 덮어쓰기를 하지 않는다.
2. 패키지 고정 목록으로 가상환경을 재구성하고 Node 잠금 파일 기준으로 의존성을 설치한다.
3. 프로젝트 이력만 복원하고 원본 대화는 보존한다. fork/resume 대상과 현재 작업 경로가 맞는지 확인한다.
4. 실행 중인 동일 이름 작업공간과 창이 있으면 재사용 여부부터 확인한다. 중복 생성하거나 서버를 재시작하지 않는다.
5. 최초 신뢰·테마·로그인은 사용자가 직접 완료한다. 실제 대화와 인수인계 응답을 읽은 뒤 로딩 완료로 기록한다.
6. 다음 개발은 지정된 데스크톱 작업본에서 진행하고, 노트북 원본과 같은 변경을 동시에 편집하지 않는다.
