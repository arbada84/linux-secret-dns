# MSI의 숏줍대본 작업 환경

검증일: 2026-11-15. 상태: **독립 작업본·이력 복사·두 에이전트 창 구성 완료, 사용자 초기 확인 대기**.

이 문서는 숏줍대본 자료 작업공간의 MSI 구성 기록이다. 운영 봇 이전이나 새 콘텐츠 제작을 수행한 기록이 아니다. 노트북 원본과 기존 MSI 보관본은 그대로 유지한다.

## 작업본과 도구

| 항목 | 구성·확인 결과 |
|---|---|
| MSI 작업 경로 | `$HOME/Projects/shortjup-new-prompts` |
| Herdr 배치 | 별도 `숏줍대본` 작업공간, 왼쪽 Codex·오른쪽 Claude |
| Herdr | 0.8.8, 기존 서버 유지 |
| Codex CLI | 0.169.0 |
| Claude Code | 2.1.321 |
| Node | 24.16.0 |
| Python | 3.12.3 |
| 프로젝트 환경 | `.venv`, `--system-site-packages`로 기존 Python 패키지 재사용 |
| 확인한 패키지 | Pillow 10.2.0, requests 2.31.0, BeautifulSoup 4.12.3 |
| pstack | 0.15.36, 프로젝트 한정 58개 스킬 경로 노출 |

자료 작업공간에는 원래 루트 Git 저장소·Node 패키지 명세가 없다. 새 Git 저장소를 초기화하거나 보관된 배포 스크립트별 의존성을 설치하지 않았다. 과거 자료 안에 있던 외부 `node_modules` 절대 링크 두 개는 새 작업본에서 제외했다. 운영 코드 경로를 가리키던 옛 문자열은 역사 기록으로 보존하며 실행 경로로 사용하지 않는다.

`MSI-HANDOFF.md`는 MSI의 현재 경로, 최초 시작 범위와 운영 금지 사항을 설명한다. 기존 `AGENTS.md`와 `CLAUDE.md` 원본은 작업본의 비공개 환경 기록에 따로 보관하고, MSI 인수인계 안내만 추가했다.

## 자료와 이력 연결

기존 MSI 보관본의 전송 결과·제외 정책을 읽고 노트북 자료와 체크섬 dry-run으로 비교했다. 복사 시점에 정책 대상 파일의 내용 차이가 없었다. 별도 작업 경로에 복사한 뒤 다시 체크섬 dry-run으로 대조했다. 삭제·원본 이동·기존 보관본 덮어쓰기는 하지 않았다.

인증·개인키·운영 SQLite/DB·가상환경·캐시는 자료 복사에서 제외한다. 보관 자료의 실제 SQLite/개인키 파일 헤더도 점검했으며 해당 파일은 발견하지 않았다. 이는 대화 속 모든 비밀 문자열을 완전히 탐지했다는 뜻이 아니다. 이력과 사적 자료는 공개 저장소에 올리지 않는다.

프로젝트에 속하는 Codex 이력 3개와 지정된 Claude 이력 1개를 시점 고정 사본으로 보관하고, MSI의 각 도구가 읽는 네이티브 이력 위치에 선택적으로 복사했다. 총 4개 이력의 파일 SHA와 크기를 검증했다. 전역 인증·다른 프로젝트 이력·도구 상태 DB는 복사하지 않았다. 원본 이력은 보존한다.

- Codex: 지정 이력에서 `codex fork <선택한_이력_ID> -C "$HOME/Projects/shortjup-new-prompts"`로 새 대화를 준비했다. 실제 시작은 읽기 전용 sandbox와 요청 시 승인을 사용한다.
- Claude: 선택한 프로젝트 이력을 새 경로의 프로젝트 이력 폴더에 두고 `--resume <선택한_이력_ID> --fork-session`으로 준비했다.
- 최초 안내는 인수인계·현재 상태 확인 후 대기뿐이다. 과거 대화의 작업 지시를 재실행하거나 새 콘텐츠 작업을 시작하지 않는다.

pstack 원본은 프로젝트의 `.agent-tools/pstack`에 보관한다. Codex에는 `.agents/skills/pstack-*` 상대 링크로 노출하고, Claude에는 `--plugin-dir` 시작 인수로 노출한다. 다른 작업공간·전역 설정은 덮어쓰지 않는다. 경로 노출과 신뢰 승인 후 실제 스킬 로딩 확인은 별도 단계다.

## 수행한 검사

- 자료 복사 전후 체크섬 dry-run: 정책 대상 파일 내용 차이 0개.
- 내보내기·마이그레이션·인계 자료 JSON 340개: 구문 읽기 성공.
- 마이그레이션 Python 스크립트 1개: AST 구문 검사 성공. 실행하지 않았다.
- 샘플 PNG: 원본 SHA 일치, 1080×1920 헤더 확인.
- 프로젝트 venv에서 Python 및 기존 이미지·HTTP·HTML 처리 패키지 import 성공.
- pstack 스킬 링크 58개 존재 확인.
- 초기 Herdr 작업공간과 사용자 포커스 보존, 새 좌우 창 생성. 다른 작업공간은 수정하지 않았다.
- 실제 터미널을 읽어 초기 화면 확인. Herdr의 `idle`/`interactive_ready`만으로 대화 로딩 완료라고 판단하지 않았다.

## 현재 남은 사용자 확인

왼쪽 Codex는 **Hooks need review** 화면이다. 신뢰 후 hook이 sandbox 밖에서 실행될 수 있다는 안내가 있으므로 사용자가 내용을 검토하고 직접 선택해야 한다. 오른쪽 Claude는 최초 테마 선택 화면이며 CLI 인증 상태 조회도 로그인 완료로 확인되지 않았다. 테마·로그인·필요한 신뢰 확인은 사용자가 직접 처리한다.

어떤 초기 확인 화면도 자동 선택하지 않았다. 따라서 이력 복사와 분기 시작 명령은 준비됐으나 **기존 대화의 실제 로딩·인수인계 응답·pstack의 런타임 로딩은 아직 확인하지 못했다.** 이를 전체 완료로 표시하지 않는다.

사용자 확인 뒤에는 각 창의 실제 응답에서 현재 경로·이력 연속성·인수인계 내용을 확인하고 대기시킨다. 예전 작업을 자동으로 재개하지 않는다. 초기 설정이 끝나도 운영 실행 승인을 받은 것은 아니다.

## 안전한 복원·재개

1. 현재 MSI 작업본과 비공개 환경 기록의 파일 목록·SHA를 먼저 확인한다. 원본 보관본에 현재 작업본을 역방향 덮어쓰지 않는다.
2. 필요한 프로젝트 이력만 별도 복사하고, 대상에 같은 이름의 다른 이력이 있으면 충돌로 멈춘다. 인증·도구 상태 DB 전체를 복구하지 않는다.
3. 인수인계와 프로젝트 지시서를 읽고 해당 Herdr 세션·작업공간·창을 실제 조회한다. 기존 창이 있으면 중복 생성하지 않는다.
4. Codex fork/Claude fork-resume으로 새 대화를 만들며 원본을 보존한다. 초기 신뢰·테마·로그인은 사용자가 직접 처리한다.
5. 자료 읽기·체크섬·구문·이미지 헤더 검사만 실행한다. 운영 DB/worker/봇/큐/예약/미디어 생성기/운영 노드를 MSI에서 시작하지 않는다.

Gemini·Antigravity 신규 호출·자동 재시도, 유료 API·예산·운영 provider 설정 변경은 수행하지 않았다. 이 페이지에는 접속 주소·인증 정보·키 경로·대화 식별자·원본 대화 내용을 기록하지 않는다.
