# Herdr용 Ghostty 1.2.3 한글 입력 구성

2026-11-12에 시스템 Ghostty 1.3.1과 별도로 구성한 실행 경로입니다. Herdr의 한국어 메뉴 패치와 실제 한글 조합 입력은 별개 문제입니다. 이 문서는 당시 파일과 시험 결과를 보관합니다. 이번 GitHub 정리에서는 GUI나 입력기를 다시 실행하지 않았습니다.

## 보존한 구성

| 자료 | 내용 |
|------|------|
| `install-manifest.json` | 커뮤니티 패키지 출처·SHA-256, 원래 설치 경로와 보존 파일 해시 |
| `config.example` | 별도 Ghostty 프로필에 명시적 설정이 없었다는 기록 |
| `../../herdr/launchers/herdr-ghostty-ko` | 사용자 홈 경로를 `${HOME}`로 일반화한 실행기 |
| `../../herdr/launchers/*.desktop.template` | Ghostty·GNOME Terminal·기본 실행 아이콘 |
| `../ime-history/` | 당시 입력 시험 스크립트, 결과와 진단 로그 |

Ghostty 1.2.3 바이너리는 원래 `~/.local/opt/ghostty-1.2.3/usr/bin/ghostty`에 따로 배치했습니다. 시스템 `/usr/bin/ghostty`와 기존 기본 터미널은 유지했습니다. 패키지는 Ghostty 원본 프로젝트의 직접 배포물이 아닌 `mkasberg/ghostty-ubuntu` 커뮤니티 패키지입니다. 보관 기록의 출처 URL이 현재도 내려받아지는지는 이번에 확인하지 않았습니다.

실행기는 `FCITX_NO_PREEDIT_APPS`를 해제하고 `GTK_IM_MODULE=fcitx`를 지정합니다. Ghostty에만 별도 `XDG_CONFIG_HOME`과 `GHOSTTY_RESOURCES_DIR`를 적용합니다. 자식 Herdr를 실행할 때는 두 변수를 제거해 기존 Herdr 설정을 사용하도록 합니다. `--gtk-single-instance=false`로 별도 창을 요청합니다.

## 과거 입력 시험 결과

시험 문장은 `한글 입력 테스트`이며, 정규화 후 기대 길이는 9글자입니다.

| 시험 | 보관 결과 | 판단 범위 |
|------|-----------|-----------|
| 초기 IBus 연결 | 입력 길이 10, 기대 9, 불일치 | 해당 시험 실패 |
| 조합 표시 분리 | 정규화 길이 7, 기대 9, 불일치 | 해당 시험 실패 |
| 별도 Xvfb 환경 | `window_not_created` | 창 생성 실패로 입력 판단 불가 |
| Ghostty 1.2.3 비교 창 | 정규화 길이 9, 기대 9, 일치 | 당시 수동 입력 문장 시험 통과 |

한 문장 시험 통과가 모든 앱·키 조합·원격 세션의 한글 입력을 보장하지는 않습니다. 실패 기록도 함께 보관했습니다.

## 새 장치에 적용하기

1. `install-manifest.json`의 패키지 출처와 해시를 확인합니다. 다운로드한 파일의 SHA-256이 기록과 다르면 설치하지 않습니다.
2. 기존 Ghostty를 교체하지 않고 별도 경로에 패키지를 풉니다. 새 장치의 라이브러리와 실행 호환성은 따로 검사합니다.
3. 실행기의 Ghostty 바이너리·리소스 경로와 Herdr 경로가 새 장치에 존재하는지 확인합니다.
4. 기존 동명 실행기가 있으면 백업한 후 수동으로 설치합니다. 실행 파일에는 실행 권한이 필요합니다.
5. 실행 아이콘의 `/home/USER/`를 실제 사용자 홈으로 바꿉니다. 기존 아이콘을 백업한 후 사용자 applications 폴더에 등록합니다.
6. 작업 중인 창을 종료하지 않고 별도 시험 창에서 직접 한글을 입력해 확인합니다.

이 자료는 자동 설치기가 아닙니다. `.desktop.template`은 경로를 바꾸기 전 실행용 파일이 아닙니다. 기존 Herdr 세션이나 서버를 종료할 필요가 없습니다.
